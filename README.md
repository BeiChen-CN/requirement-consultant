# requirement-consultant

将模糊的项目想法通过 5 阶段自适应引导转化为完整项目计划书。

## 解决什么问题

大量非技术用户使用 AI 开发项目时面临：

- **需求说不清** — "我想做个网站"，但说不清具体要什么功能
- **技术选不了** — 不知道该用什么编程语言、框架、数据库
- **UI 设计难** — 不是设计师，描述不出想要的视觉风格
- **逻辑理不顺** — 用户思维和开发者思维之间有鸿沟

这个 skill 让 AI 扮演产品经理 + 技术顾问，通过逐题引导帮用户把模糊想法变成可直接执行的项目计划书。

## 工作方式

5 个阶段，逐题引导，自适应调整：

```
用户说："我想做个网站"
    ↓
阶段 1：愿景探索 — 用类比锚定方向（"你说的像 XX 吗？"）
    ↓
阶段 2：需求拆解 — 逐个功能点确认，动态增减
    ↓
阶段 3：用户场景 — 确定角色、流程、边界条件
    ↓
阶段 4：技术选型 — 根据需求自动推荐，大白话解释
    ↓
阶段 5：UI 风格 — 生成 HTML 原型，至少 3 套方案供选择
    ↓
输出：完整项目计划书 + AI 开发者角色卡
```

### 核心特点

- **逐题引导** — 每次只问一个问题，回答后 AI 分析再问下一个
- **自适应** — 根据每条回答动态调整后续问题，不问已知信息
- **大白话** — 避免技术术语，必要时附上通俗解释
- **类比引导** — 用生活化例子帮助理解抽象概念
- **HTML 可视化** — UI 决策点生成实际可预览的原型页面
- **动态风格** — 根据用户回答自动创建设计方案，不套用固定模板

## 输出物

引导结束后生成一份项目计划书，包含 9 个章节：

| 章节 | 内容 |
|------|------|
| 项目概述 | 类型、目标、一句话描述 |
| 目标用户与角色 | 角色列表和使用场景 |
| 功能清单 | 功能名称、描述、优先级 |
| 用户操作流程 | 每个角色的操作步骤 |
| 技术选型 | 语言、框架、数据库、部署方式 |
| UI 设计方向 | 风格、配色、布局偏好 |
| 边界条件与约束 | 限制、异常处理、兼容性 |
| 待确认事项 | 遗留问题 |
| AI 开发者角色卡 | 让后续 AI 直接进入开发状态 |

### AI 角色卡

计划书末尾嵌入一个 AI 开发者角色定义，包括身份、技术栈、沟通风格、开发优先级、分步开发规则和禁止事项。拿到计划书的 AI 可以立即开始开发，无需额外沟通。

## 文件结构

```
.claude/skills/requirement-consultant/
  SKILL.md                    # 主 skill 文档
  html-template-guide.md      # HTML 可视化参考指南
```

## 快速开始
方案一：导入到 Trae
根据 Trae 官方技能说明，Skill 是一个包含 SKILL.md 的文件夹，可通过 Settings -> Rule & Skills -> Skills -> Create 导入。你可以直接下载或克隆本仓库，然后导入根目录中的 SKILL.md。

方案二：放到本地 Skills 目录
如果你使用兼容 SKILL.md 的技能目录约定，也可以把整个文件夹放到本地技能目录，例如：

Windows Trae：%USERPROFILE%\.trae\skills\my-planning-skill
Claude Code：~/.claude/skills/my-planning-skill

## 使用方式

在claude code中调用：

```
/requirement-consultant
```

或用自然语言描述你的需求，AI 会自动匹配此 skill。

## 适用场景

- 有想法但不知道怎么开始的创业者
- 想让 AI 帮忙做项目但描述不清需求的用户
- 需要一份结构化项目计划书再动手的开发者

## 不适用场景

- 已有明确技术规格书或 PRD
- 只是想修改现有代码的某个功能
- Bug 修复或代码调试
