# requirement-consultant

Superpowers skill：将模糊的项目想法通过 5 阶段自适应引导转化为完整项目计划书。

## 解决什么问题

大量非技术用户使用 AI 开发项目时面临：

- **需求说不清** — "我想做个网站"，但说不清具体要什么功能
- **技术选不了** — 不知道该用什么编程语言、框架、数据库
- **UI 设计难** — 不是设计师，描述不出想要的视觉风格
- **逻辑理不顺** — 用户思维和开发者思维之间有鸿沟
- **成本没概念** — 不知道项目上线后要花多少钱
- **安全意识弱** — 涉及用户数据时不知道要考虑什么

这个 skill 让 AI 扮演产品经理 + 技术顾问，通过逐题引导帮用户把模糊想法变成可直接执行的项目计划书。

## 工作方式

5 个阶段，逐题引导，自适应调整：

```
用户说："我想做个网站"
    ↓
阶段 1：愿景探索 — 用类比锚定方向 + 竞品分析
    ↓
阶段 2：需求拆解 — 逐个功能点确认，动态增减
    ↓
阶段 3：用户场景 — 角色、流程、边界、空/加载/错误状态
    ↓
阶段 4：技术选型 — 自动推荐 + 成本预算 + 时间估算 + 安全评估
    ↓
阶段 5：UI 风格 — 检测设计专业度，生成 HTML 原型，3 套方案
    ↓
输出：13 章完整项目计划书 + AI 开发者角色卡
```

### 核心特点

- **逐题引导** — 每次只问一个问题，回答后 AI 分析再问下一个
- **自适应** — 根据每条回答动态调整后续问题，不问已知信息
- **状态可追踪** — 内部维护需求模型，阶段间状态不丢失，支持随时回退
- **会话可控** — 支持暂停、重新开始、快速模式、直接输出、局部修改等 7 种控制指令
- **大白话优先** — 避免技术术语，必要时附上通俗解释
- **术语自适应** — 根据用户专业度自动切换大白话 / 中等术语 / 专业术语
- **HTML 可视化** — UI 决策点生成实际可预览的原型页面，三端适配（移动端/平板/桌面端）
- **动态风格** — 根据用户回答自动创建设计方案，不套用固定模板

## 输出物

引导结束后生成一份项目计划书，包含 13 个章节：

| 章节 | 内容 |
|------|------|
| 项目概述 | 类型、目标、一句话描述、竞品参考 |
| 目标用户与角色 | 角色列表和使用场景 |
| 功能清单 | 功能名称、描述、优先级（核心/重要/锦上添花） |
| 用户操作流程 | 操作步骤 + 空状态 + 加载状态 + 错误状态 + 边界情况 |
| 技术选型 | 语言、框架、数据库、状态管理、部署、CI/CD、监控 |
| 数据模型 | 核心实体、字段、关系（大白话描述） |
| 环境配置 | 开发环境、账号注册、密钥配置 |
| UI 设计方向 | 风格、配色、布局、响应式断点 |
| 页面清单与路由 | 页面列表、URL、跳转关系、主要组件 |
| API 接口清单 | 接口名称、用途、输入输出（如适用） |
| 成本预算 | 域名、服务器、第三方服务、免费额度 |
| 开发时间线 | 乐观/正常/保守三档估算 |
| 安全与隐私 | 数据存储、敏感信息保护、输入校验、权限控制 |
| 边界条件与约束 | 限制、异常处理、兼容性要求 |
| 项目目录结构 | 推荐的文件夹结构和关键文件 |
| 待确认事项 | 遗留问题和下一步行动 |
| AI 开发者角色卡 | 让后续 AI 直接进入开发状态 |

### AI 角色卡

计划书末尾嵌入一个 AI 开发者角色定义，包括身份、技术栈、沟通风格、代码风格、错误处理策略、测试策略、响应式设计断点、开发优先级、分步开发规则和禁止事项。拿到计划书的 AI 可以立即开始开发，无需额外沟通。

## 自适应机制

### 内部需求模型

整个引导过程中 AI 维护一个结构化的内部需求模型，覆盖：

- 项目信息（类型、目标、类比产品）
- 竞品分析结果（喜欢/不喜欢/决定借鉴）
- 功能清单（名称、描述、优先级）
- 用户角色与操作流程（含空状态、加载状态、错误状态）
- 技术选型（语言、框架、数据库、第三方服务）
- 成本预算与开发时间估算
- 安全与隐私需求
- UI 风格偏好（配色、布局、组件风格）
- 用户拒绝项和待确认事项

每个阶段结束时更新模型，"回到上一步"时从模型恢复，不会丢失已收集的信息。

### 讲解深度自适应

技术方案的讲解深度根据用户水平自动调整：

| 用户水平 | 讲解方式 |
|----------|---------|
| 完全不懂 | 生活类比开头（"数据库就像 Excel 表格"），讲影响不讲原理 |
| 有点基础 | 类比 + 适当术语 + 社区生态 |
| 有开发经验 | 直接用术语，重点讲技术取舍和选型对比 |

### 设计术语自适应

UI 风格介绍根据用户的设计知识水平自动切换术语体系：

| 风格 | 零基础 | 有设计基础 | 专业 |
|------|--------|-----------|------|
| 简洁现代 | 像苹果官网，干净清爽 | 极简主义，扁平化设计 | Minimalist / Swiss Design |
| 活泼年轻 | 像小红书，颜色鲜艳 | 高饱和色彩，微动效 | Gen Z 视觉语言，Glassmorphism |
| 稳重商务 | 像银行 APP，看着靠谱 | 企业级 UI，信息密度适中 | Corporate UI，Material Design 3 |

## 会话控制

用户可以在任何时候发出控制指令：

| 指令 | 行为 |
|------|------|
| 暂停 / 先到这里 | 保存中间状态，提示下次可继续 |
| 重新开始 | 清空进度，回到阶段 1 |
| 快速模式 | 跳过已有信息，用默认值填充，直接输出计划草稿 |
| 直接给我计划书 | 已有足够信息时立即生成，缺失部分标记"待确认" |
| 修改 XX 章节 | 局部修订，自动检查受影响的其他章节 |
| 回到上一步 | 从模型恢复目标阶段，已收集信息保留 |

## HTML 可视化

UI 决策点（阶段 5）生成实际可预览的 HTML 原型文件：

- **三端预览** — 移动端（375px）、平板端（768px）、桌面端（1280px）并排展示
- **17 个组件模板** — 导航栏、底部导航、侧边栏、卡片、按钮、输入框、表单、表格、弹窗、Tab、轮播图、空状态、骨架屏、加载指示器、页脚等
- **内联样式** — 浏览器直接打开，无外部依赖
- **项目相关内容** — 不用 lorem ipsum，占位文本与项目相关
- **深色模式** — 可选提供明暗两套配色方案
- **触控规范** — 移动端可点击元素不小于 44×44px
- **字号层级** — 6 级字号 × 3 端适配

文件保存到 `temp/mockups/` 目录。

## 使用方式

在支持 Superpowers 技能框架的 AI 助手中直接调用：

```
/requirement-consultant
```

或用自然语言描述你的需求，AI 会自动匹配此 skill。

## 适用场景

- 有想法但不知道怎么开始的创业者
- 想让 AI 帮忙做项目但描述不清需求的用户
- 需要一份结构化项目计划书再动手的开发者
- 非技术产品经理需要将想法转化为开发者能理解的需求

## 不适用场景

- 已有明确技术规格书或 PRD
- 只是想修改现有代码的某个功能
- Bug 修复或代码调试
